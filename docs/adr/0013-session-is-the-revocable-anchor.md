# Session is the revocable anchor

A Session is the durable record of one authentication of one Identity — it *is* the signed-in device, surviving browser closes, carrying recognizable device metadata (device, time, last-seen) so a non-expert End User can identify it in a list. One sign-in produces one Session; it parents the platform SSO cookie and every refresh token minted through any Application's flow — Zotac's and CodeBoard's tokens are its children, not independent credentials. Revocation cascade: kill a Session and the cookie dies and all descendant refresh tokens are revoked immediately; access tokens are deliberately untracked and die naturally within a short (minutes) TTL. So "revocation is immediate" (ADR-0006) honestly means: seconds for anything that asks the platform; at most one short access-token TTL for Applications that validate offline. Password change revokes all *other* Sessions and keeps the one where the change happened. Logout means revoking the current Session — nothing more mystical; Applications lose the user as their tokens validate. Costs accepted as product commitments: short access-token TTLs and refresh-token rotation as the norm. Rejected: stateless tokens as the session (nothing to revoke, the dashboard lies); per-Application sessions (no SSO — fragments the person).
