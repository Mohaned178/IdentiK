# Deletion means anonymization — for Identities and Applications

Deleting an Identity destroys PII (email, credentials, external links) irreversibly, revokes Sessions and Enrollments, and preserves audit history against a pseudonymous shell — because a security product must still answer "who signed in from that IP last Tuesday?" after the person is gone. The email becomes immediately reusable by a fresh, unlinked Identity that inherits nothing. Not recoverable, by design. Rejected: hard delete (destroys the security product the customer bought); soft delete/tombstone (retains data while lying about destruction, and occupies the email). The same pattern applies to Application deletion: Enrollments removed, credentials revoked immediately, audit pseudonymized — but Identities survive, including those orphaned by the deletion, because Identities belong to the Organization, not the Application (ADR-0004). Orphan hygiene is an Organization concern, not something Application deletion silently does. A reversible intermediate Disabled state exists for Applications: new authentication blocked, app-minted refresh tokens revoked immediately, Sessions survive.
