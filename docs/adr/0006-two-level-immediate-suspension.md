# Two-level immediate suspension with honest propagation

Two distinct dashboard actions exist: suspend from Application (Enrollment-level) and suspend Identity (Organization-wide). Both take effect immediately at the platform: the End User's live platform Session is revoked within seconds and new authentication is blocked at the affected scope. Suspension is a security action, not a bookkeeping flag — which commits the platform to server-revocable Sessions (ADR-0013). The propagation to client applications is honest, not magical: the platform kills its Session instantly; each Application loses the user as it validates tokens (its own app-level session is the Application's, not ours). The dashboard must not promise what the platform cannot deliver. Rejected: block-new-authentication-only suspension (a "suspended" user keeps using the app for hours); Application-only suspension (kills the management capability the product exists to provide). Hard lockout is deliberately not a thing (ADR-0020) — suspension is the only "this actor is done" decision, and only Administrators make it.
