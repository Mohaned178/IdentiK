# Administrators manage state, never credentials

Administrators see everything security-relevant about an End User (email, verification state, MFA state, Enrollments, active Sessions, authentication activity) and pull state levers only: suspend/unsuspend, revoke Sessions, force password reset (delivered to the existing verified email), anonymize. They can never see or set anything that authenticates — no reading passwords (trivially), no setting passwords on a user's behalf, no changing a user's email. Impersonation does not exist. Principle: an Administrator must never be a takeover oracle for every Identity in the Organization. Consequences: email changes belong to End-User self-service in the Account Center with verification of the new address — so a minimal End-User self-service surface (email change, password change, Session visibility) is part of the product. The same principle governs the platform's own population: invited Administrators set their own passwords.
