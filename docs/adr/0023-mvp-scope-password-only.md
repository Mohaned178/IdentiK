# MVP scope: password-only first release

The first release ships: Bootstrap Ceremony + default Organization (ADR-0021); Owner/Member roles + email invitation (ADR-0016, ADR-0021); Application registration with Web + SPA/Mobile types, full credential lifecycle, exact-match redirect URIs (ADR-0009, ADR-0010); email+password sign-up with the verification gate (ADR-0011); sign-in/sign-out, forgot/reset (ADR-0011); Account Center — Sessions, password change, verified email change (ADR-0018); user management — view, two-level suspension, revoke Sessions, force reset, anonymize (ADR-0006–0008); Application disable/delete (ADR-0007); full standard OIDC — authorization code + PKCE, JWT/JWKS/discovery/userinfo/revocation/introspection (ADR-0015); first-class unified audit surface (ADR-0020); Management API with the dashboard as first client (ADR-0019); per-Organization branding and policy (ADR-0022).

Explicitly deferred, each as a designed-for additive increment: TOTP MFA + recovery codes first (ADR-0017); social login / External Identities second (ADR-0012); machine-to-machine Application type + programmatic Management API access; consent screens + third-party Applications (ADR-0014 guardrail); Application environments (ADR-0009 guardrail); hosted multi-tenant mode; Application role storage; impersonation; SMS/email-OTP factors.

The coherence demo the release must satisfy end-to-end: the Instance bootstraps → default Organization → Zotac registered as a Web Application → Mohamed signs up, verifies, signs in to Zotac via standard OIDC → the Owner suspends him, revokes his Sessions, anonymizes him — every step observable from outside at the HTTP and email boundaries. Rejected: MVP-plus-Google (the full external-identity linking matrix in an unshipped core loop) and the kitchen sink.
