# Administrator bootstrap and invitation lifecycle

The first Owner is created by a Bootstrap Ceremony: first boot of an Instance creates the default Organization and a one-time, expiring setup flow initiated from the install process — nobody invites the first Administrator; the Instance does. Thereafter, Owners invite additional Administrators by email; the invitee receives a link and sets their own password (ADR-0008's principle applied to the platform's own population — the inviter never chooses a credential). Membership is a scoped record — Administrator + Organization + role — so one human can hold different roles in different Organizations when hosted mode arrives. There is no self-serve path to administration and no open Organization sign-up. Rejected: config-file/CLI Administrator creation (no "who added Layla, when" in audit — resurrects the unattributed-admin-action hole); open sign-up (any instance foothold could mint an Organization and its Owner). Pleasing recursion: the platform obeys the membership rules it sells.
