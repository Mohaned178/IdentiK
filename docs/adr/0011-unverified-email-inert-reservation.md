# Unverified email is an inert reservation

An Identity whose email is unverified cannot authenticate, enroll, or consent — it exists only as a flagged placeholder in the dashboard holding the email until someone proves mailbox control. This yields a single clean invariant: every authenticated Identity has a verified email, so Applications never face an unverified-user policy question and the audit trail never contains "logged in with an email we never proved." Pre-claimed emails are self-healing without Administrator intervention: the mailbox's true owner attempting sign-up is told "an identity with this email already exists — sign in instead"; forgot-password sends a reset link to the owner's own inbox; clicking it proves mailbox control. Any proof of mailbox control — verification link or password-reset link — marks the email verified: one concept, two entry points. Accepted cost: a working SMTP path is a hard prerequisite for any login, which the self-hosted deployment model already assumes.
