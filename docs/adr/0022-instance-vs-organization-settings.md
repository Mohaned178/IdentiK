# Instance settings vs Organization settings: trust fabric vs policy

The boundary is drawn along who must be trusted to change it. Instance-scoped (held in deployment configuration, out-of-band from the dashboard): infrastructure config (SMTP transport, database), signing keys, trusted external identity providers, instance-level brand. Organization-scoped (dashboard-governed by Owners, audit-logged): branding, password policy, session timeout policy, the default Application list. A bad actor in the trust fabric compromises every Organization; Organization policy affects only that Organization — and in hosted mode we-the-operator must never be setting an individual customer's password policy. Consequence: password policy is per-Organization, which keeps the multi-Organization future (ADR-0021) honest.
