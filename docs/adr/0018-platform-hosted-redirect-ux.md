# Platform-hosted redirect UX and Account Center

All authentication UI lives on the platform Instance's own pages — the classic OIDC authorization-endpoint redirect model, what every off-the-shelf library expects — themed per-Organization (logo, colors). End-User self-service lives in a platform-hosted Account Center: active Sessions, password change, email change (effective only after the new address is verified, preserving the verified-email invariant and email uniqueness), connected Applications (informational). Client Applications link to the Account Center; they never embed it. Accepted cost: the login page carries the Instance's domain, not the client's — the standard tradeoff of every serious IdP; per-Organization theming is the honest mitigation. Rejected: embedded components (Clerk-style widgets require headless APIs and iframe machinery, break the zero-SDK interop promise, and re-open the phishing-skinny-lookalike questions the redirect model exists to close); hybrid (two integration models forever for one screen's pixel control).
